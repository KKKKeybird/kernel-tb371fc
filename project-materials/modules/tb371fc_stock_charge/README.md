# TB371FC R8 原厂停充接口与小米充电保护桥接

将小米“电池保护”页面接到联想原厂 `charge_disable` 控制，替换 R8 作者的 `lwky_smart_charge_hyper`。
这是复用原厂硬件停充接口、适配小米上层选项；不是声称完整复制 ZUI 的全部40–60%保养策略。

## 三个选项

| 小米选项 | 实机控制值 | 本模块行为 |
|---|---:|---|
| 正常充满 | 0 | 解除本模块停充请求；原温控仍可限流或停充 |
| 电池健康保护 | 2 | 达到80%停充，降到78%恢复；重新选择时重新判断 |
| 旁路充电 | 1 | 外部电源存在时立即停止电池充电，保留USB输入，不要求先到80% |

健康保护识别小米原有 `getThisTimeNoProtect` 的 `once_no_protect=1` 临时充满请求。
定期充满的日程由小米原有服务负责，本模块不另造充满周期；原有服务不发请求时，不能保证该文案中的周期充满会触发。
拔掉外部电源时解除本模块停充请求；重新插入后按当前选项处理。

## 安装

仅适配本项目 `TB371FC-HyperOS3-20261103-full` R8、Android15、已经实测的 **HyperOS #25 内核**。
其他内核即使同为4.19.325也拒绝安装。需要先升级时，使用同订阅的内核更新器并按其提示主动确认刷入。

1. 先选择“正常充满”，接上电源，让旧程序退出假旁路状态。
2. 在 BakaSU / KernelSU 中安装本模块ZIP，重启。
3. 从原来的“电池保护”页面选择模式，无须使用额外应用。

安装器不清除热限制。若有其他停充控制器、联想 `bp_enable` 保护或旧的输入暂停仍在生效，会拒绝接管。
安装包不是整个GitHub源码ZIP。禁用或卸载并重启，会恢复ROM原有充电控制程序。
模块“操作”按钮只显示状态和诊断日志，不刷内核、不切换选项。

## 与现有模块的关系

不替换设置、安全中心或PowerKeeper APK，不刷boot，不修改充电器协商、JEITA、温度读数或浮充电压。
不覆盖电池容量统计、手写笔、分屏、扬声器旋转模块的文件。
不修改PPS温度实验模块；该实验仍需其自身按钮启动，实验运行期间不建议同时测试本模块。
不能与另一个同时写 `charge_disable` 的充电控制器并用；内核该接口共用USER投票。

## 验证范围与保护

2026-11-14已验证USB/普通PD路径的停充与恢复：电池电流降到0，USB输入保留；不是仅凭UI“不充电”字样判断成功。
80/78%门槛做了纯策略状态测试，不伪造实机SOC进行验收。
**PPS且充电泵已开启的场景尚未实测。** 停充15秒后若充电泵仍开，或电池仍以超过200mA充电，桥接会退出并恢复旧控制，不伪造成功状态。
这不证明物理电池已经断开；瞬时负载和电源不足时，电池仍可能参与供电。

只通过 `charge_disable` 申请停充；运行中不写 `input_suspend`、`charge_control_limit`、温控或电量节点。
旧程序由init停止，开机在post-fs-data阶段阻止其自启；模块退出时恢复它。
桥接进程和监督进程相互检查存活，正常退出、禁用或子进程退出时释放自身请求；系统重启会重新初始化硬件。
同进程每秒读取一次小米安全设置，30秒检查一次临时充满请求；不持有唤醒锁，不每秒创建子进程。
状态在 `/dev/tb371fc_stock_charge/status`；日志在 `/data/adb/tb371fc-stock-charge.log`。

## 源码与重建

源码位于仓库 `project-materials/modules/tb371fc_stock_charge/src/`。
使用已有JDK21和R8/D8：

```sh
python3 build.py --java-home /path/to/jdk21 --r8-jar /path/to/r8.jar
python3 package.py --output /tmp/TB371FC-StockCharge-v1.0-test1.zip
```

无需解包完整ROM、修改APK或编译内核。
