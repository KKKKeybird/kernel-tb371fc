# TB371FC R8 电池容量统计修复 v1.0

修正本项目 TB371FC HyperOS 3 R8 向 Android 上报的容量信息：满充容量从固定
10200mAh 改为电量计动态估算值，`charge_counter` 从错误的健康度数字改为
剩余容量（µAh）。按用户选定的官方规格口径，设计容量基准保持 10200mAh。

## 适用范围

- 本项目构建标识 `TB371FC-HyperOS3-20261103-full`（R8）。
- Android 15 / SDK 35，移植设备身份 `sheng`，内核 `4.19.325-perf++`。
- MM8013C06 电量计位于 I2C bus 1、地址 0x55。
- BakaSU / KernelSU；安装器会核对上述身份及必要节点。

这是本项目专用兼容模块，不适用于其他 ROM 或其他型号。当前实机为此 ROM 的
SELinux Permissive 配置；没有另外验证自行改成 Enforcing 的配置。

## 使用

从 BakaSU 已添加的本项目订阅下载本模块，或安装 Release 附件
`TB371FC-BatteryStats-v1.0.zip`，安装后重启。模块包含 `updateJson` 更新地址。
开机完成后开始工作，每30秒读取一次电量计，使用内存中的文件临时挂载六个
容量节点。模块的“操作”按钮可显示最近一次采样和日志位置。

在“电池保护”页面可看到10200mAh设计容量、动态实际容量及两者的比例。
这个比例是电量计估算值与所选设计基准的比值，不能代替完整的电池健康检测。

禁用模块后，运行中的脚本会在30秒内退出并撤销挂载；卸载脚本也会停止它。
重启且不加载模块时，恢复原始驱动上报。异常退出、连续三次样本异常或采样
失败时也会尝试回退；卸载、禁用不会清空历史电量统计。

## 数据口径和实现

- 原厂 MM8013C06 驱动导出的满充容量对应寄存器0x12；本模块沿用此机型的
  读取口径。剩余容量读取0x10，百分比对照0x2c。
- 0x3c 的10000mAh原始值仅用于样本校验和诊断；上报给 Android 的设计基准
  使用联想官方标注的10200mAh典型容量，不将两者混为同一来源。
- 典型容量来源：[联想商城骁龙870版小新 Pad Pro 12.7规格](https://item.lenovo.com.cn/product/1031777.html)。
- 只发送寄存器地址并读取数据，不写电量计控制/配置寄存器。
- 对 `bms` 与 `battery` 下的 `charge_counter`、`charge_full`、
  `charge_full_design` 做临时文件挂载。内核内部的 `get_property` 未被修改。
- 8位十进制数字加换行，使用前导零保持文件长度稳定，没有空格；兼容安全中心
  `readLine()` 后直接 `Integer.parseInt()` 的读取方式。
- I2C失败或样本越界时不发布新值；容量比例与原始百分比相差过大时拒绝样本。
  初始样本不合格时不建立挂载，连续三次失败时退出并恢复原始节点。
- 对六个目标节点有已有挂载的情况拒绝覆盖；回退仅卸载自身拥有的挂载。

首次启用、停用会切换累计电量数据的口径，切换附近的历史耗电记录不能直接
用来比较修复前后的功耗。模块不重置 BatteryStats，不更改电量百分比。

本模块没有PD解锁、充电泵温度补丁、旁路策略或温控修改，也没有降低实际功耗
或提高充电功率的功能。

## 构建

```sh
python3 build-zip.py --output /tmp/TB371FC-BatteryStats-v1.0.zip
```

构建只使用标准库和本目录列出的模块文件，不需要ROM镜像或APK。ZIP的成员和
时间戳固定，可重复构建；脚本与变更记录随源码保留。
