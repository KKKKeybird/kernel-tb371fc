# TB371FC R8 原厂充电控制与独立旁路供电

仅支持本项目R8、Android15、HyperOS #25内核，以及精确匹配的安全中心和设备配置。以KernelSU/BakaSU模块交付，不刷ROM或内核。

## 原页面四档

安装后重启，从“设置 → 电池 → 电池保护”选择：

| 选项 | 行为 |
|---|---|
| 正常充满 | 允许正常充电；硬件温控仍可限流或停充 |
| 智能充电保护 | 保留小米原生NightChargeProtectManager的学习、历史统计、闹钟和恢复时机；模块只转接其硬件控制请求 |
| 电池健康保护 | 约80%停止、78%恢复，识别小米原生本次充满请求 |
| 旁路供电 | 接电且亮屏解锁使用时优先旁路；息屏或电量降到20%恢复充电，恢复到25%再允许旁路；供电不足暂时退出60秒再试 |

旁路策略参考已有厂商的场景启停与低电量恢复思路；本机20/25%回差和供电不足回退是适配设计，不是声称复制三星全部条件。三星的PPS/25W门槛不能直接套用于联想硬件。

旁路使用联想原厂charge_disable，只停电池充电、保留USB输入。不使用最高热等级冒充旁路，不暂停USB，不伪造电流或温度。弱电源或瞬时峰值负载下，电池仍可能参与供电，不能把它解释为物理断开电池。

## 智能保护的已实现和未验收边界

R8原本关闭了夜间保护和AI预测能力，健康保护能力位也未打开。模块在适配器运行期间，临时开启对应的原生能力；退出会恢复原值，且不写入持久化属性存储。

预测代码、条件判断、充电记录和闹钟算法保留原样。只转接setNightChargingState、getNightChargingState、smart_chg及模式切换等入口，向原厂charge_disable提出请求。

刚启用时可能缺少历史记录；白天或不满足原生条件时正常充电是预期行为。**真实夜间预测准确性、预计使用前提前充满、跨多天的周期充满，仍需要自然使用验收。** 不以固定时间表或固定80%限充冒充原生预测。

## 安装和回退

1. 安装前先选择“正常充满”，让旧程序退出输入暂停或假热限制状态。
2. 安装发布附件ZIP并重启。不能把整个仓库源码ZIP当作模块。
3. 模块在开机后临时覆盖安全中心的相关入口；原系统APK不被写回修改。仅classes3.dex改变，预测管理器的方法体保留。
4. 若桥接异常退出，释放自身停充请求、撤销界面覆盖和能力属性；新增第四档会退回正常充电。禁用/卸载并重启，完整恢复原ROM。

安全中心更新或原包哈希不匹配时拒绝强盖旧版本。该版本仅针对本项目R8，不承诺任意安全中心版本自动兼容。

## 兼容范围

- 与现有电池容量统计、手写笔、分屏、扬声器旋转和内核更新器无文件覆盖冲突。
- 另校正sheng.xml中5000mAh的静态容量为10200mAh，其余功能标志全部保留。
- 不修改JEITA、PD/PPS限流、充电泵温度读数或电量百分比。
- PPS泵已开启的场景尚未实测；若停充15秒后泵仍开或仍持续超过200mA充电，会退出并回退。请勿同时运行PPS实验模块的限时测试。
- 不与另一个直接写charge_disable的控制器并用，该接口共享USER投票；发现联想bp_enable占用时拒绝接管。

## 源码和诊断

状态：`/dev/tb371fc_stock_charge/status`。日志：`/data/adb/tb371fc-stock-charge.log`。模块“操作”按钮显示状态。

使用已有JDK21、R8/D8及dexlib2/Guava构建依赖：

```sh
python3 build.py --java-home /path/to/jdk21 --r8-jar /path/to/r8.jar
python3 build-ui.py /path/to/original/SecurityCenter.apk --output-dex /tmp/classes3.dex --deps /path/to/dexlib-deps
python3 package.py --ui-dex /tmp/classes3.dex --output /tmp/TB371FC-StockCharge-v1.1-test3.zip
```

只读取所需的一个DEX。安装器从本机原APK流式生成临时覆盖文件，无须解包完整ROM。
`build-ui.py` 也接受 `--base-dex`，用于从已提取且SHA-256匹配的原
`classes3.dex` 重建；原DEX SHA-256为
`ca3219d74a94829904cd1adab6edcce7cb97f8db7b0c9f02261dccfb88e81537`。
